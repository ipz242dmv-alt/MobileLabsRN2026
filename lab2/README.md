# Лабораторна робота №2

**Тема:** Віртуалізація списків та побудова навігації.

**Мета:** сформувати практичні навички застосування інструментів віртуалізації списків для оптимізації рендерингу даних, а також проєктування ієрархічних систем навігації та захищених маршрутів у середовищі Expo Router.

## Опис проєкту

Застосунок «Новини політехніки»: користувач входить у систему й потрапляє в захищену частину з боковим меню, де є стрічка новин і довідковий центр.

| Вимога | Реалізація |
|---|---|
| Глобальний стан авторизації | `context/AuthContext.jsx`: `isAuthenticated`, `login()`, `logout()`. Провайдер обгортає `app/_layout.jsx` |
| Екран входу (публічний) | `app/login.jsx`: форма з валідацією пошти та пароля. Після входу `<Redirect href="/" />` автоматично переводить у застосунок |
| Захищена Drawer-навігація | `app/(drawer)/_layout.jsx`: неавторизованого користувача перенаправляє `<Redirect href="/login" />`, авторизованому показується `<Drawer>` з власним вмістом і кнопкою «Вийти» (`logout()`) |
| Вкладений Stack | `app/(drawer)/(news)/_layout.jsx` — `<Stack screenOptions={{ headerShown: false }}>`, щоб не дублювати заголовок Drawer |
| Стрічка новин (FlatList) | `app/(drawer)/(news)/index.jsx`: 100 новин на старті, Pull-to-Refresh (`RefreshControl`), Infinite Scroll (`onEndReached` + `onEndReachedThreshold={0.5}`, по 20 новин, до 300), `getItemLayout`, картка в `React.memo` |
| Деталі новини | `app/(drawer)/(news)/[id].jsx`: `useLocalSearchParams()` отримує `id` |
| Довідковий центр (SectionList) | `app/(drawer)/faq.jsx`: запитання згруповані за темами, липкі заголовки секцій, відповідь розгортається натисканням |

Безпечні зони екрана (виріз, статус-бар, системна панель) обробляє `react-native-safe-area-context` (`SafeAreaProvider`, `SafeAreaView`).

## Відповіді на контрольні запитання

**1. Як працює вкладена навігація в архітектурі Expo Router?**

У Expo Router навігатори вкладаються через структуру папок. Кожна папка з `_layout.jsx` — окремий навігатор, а екрани в ній є його маршрутами. У цьому проєкті кореневий `app/_layout.jsx` — це Stack, всередині нього `(drawer)/_layout.jsx` — Drawer, а в ньому `(news)/_layout.jsx` — ще один Stack. Папки в дужках — **групи маршрутів**: вони впливають на вкладеність навігаторів, але не додаються до URL, тому стрічка новин відкривається за адресою `/`, а деталі — за `/5`. Перехід між екранами вкладеного Stack (`router.push('/5')`) додає екран у стек усередині Drawer, а меню й заголовок Drawer лишаються. Заголовок вкладеного Stack вимкнено (`headerShown: false`), щоб не було двох заголовків.

**2. Яким чином реалізується захист маршрутів від неавторизованого доступу?**

Стан авторизації зберігається в React Context (`AuthContext`), а провайдер обгортає всю навігацію в кореневому layout. Layout захищеної групи `(drawer)/_layout.jsx` читає `isAuthenticated` і, якщо користувач не увійшов, повертає `<Redirect href="/login" />` замість навігатора. Через це жоден екран групи, навіть відкритий за прямим посиланням, не рендериться без входу. Екран входу працює навпаки: якщо користувач уже авторизований, він переходить на `/`. Після `logout()` стан змінюється, layout перемальовується, і користувача повертає на вхід. (У новіших версіях Expo Router для цього також є `<Stack.Protected guard={...}>`.)

**3. Чим FlatList відрізняється від ScrollView та що таке віртуалізація списків?**

`ScrollView` рендерить **усі** дочірні елементи одразу, навіть невидимі. Для 100+ карток із зображеннями це велике споживання пам'яті, повільний перший рендер і просідання FPS. `FlatList` побудований на `VirtualizedList` і рендерить лише елементи у видимій області та невеликому буфері навколо неї (`windowSize`, `initialNumToRender`, `maxToRenderPerBatch`). Елементи, що вийшли за межі вікна, демонтуються, а замість них лишається порожній простір потрібної висоти. Це і є **віртуалізація**: розмір дерева компонентів залежить від розміру екрана, а не від кількості даних. Додатково `getItemLayout` дає змогу не вимірювати елементи (вони мають фіксовану висоту), а `React.memo` не дає повторно рендерити вже показані картки, коли до масиву додаються нові новини. Крім того, у `FlatList` є вбудовані Pull-to-Refresh, `onEndReached`, роздільники, заголовок і футер.

**4. Як отримати параметри динамічного маршруту на цільовому екрані в Expo Router?**

Файл із назвою в квадратних дужках, наприклад `[id].jsx`, є динамічним маршрутом. На цільовому екрані параметр отримують хуком `useLocalSearchParams()`: `const { id } = useLocalSearchParams();`. Параметри завжди приходять рядками, тож за потреби їх конвертують (`Number(id)`). Передати параметр можна через шлях (`router.push('/5')`, `<Link href="/5">`) або об'єктом (`router.push({ pathname: '/[id]', params: { id: 5 } })`). Є ще `useGlobalSearchParams()`, але він оновлюється при зміні URL будь-якого екрана, тому для конкретного екрана рекомендують `useLocalSearchParams`.

**5. Яку структуру даних приймає компонент SectionList?**

Проп `sections` — це масив об'єктів-секцій. Кожна секція має обов'язкове поле `data` (масив елементів цієї секції) і довільні додаткові поля, наприклад `title` чи `icon`, які використовуються в `renderSectionHeader`:

```js
[
  { title: 'Обліковий запис', icon: 'person-circle-outline', data: [{ id: 'a1', q: '…', a: '…' }, …] },
  { title: 'Стрічка новин', data: [ … ] },
]
```

`renderItem` отримує `{ item, index, section }`, `renderSectionHeader` — `{ section }`. Секція також може мати власні `renderItem` і `keyExtractor`.

## Висновки

У роботі реалізовано ієрархічну навігацію Expo Router (Stack → Drawer → Stack) з групами маршрутів, глобальний стан авторизації через Context і захист маршрутів через `<Redirect>`. Стрічку з сотнями новин побудовано на `FlatList` з оновленням жестом, нескінченним прокручуванням і оптимізаціями (`getItemLayout`, `React.memo`, стабільні колбеки через `useCallback`). Довідковий центр із згрупованими даними — на `SectionList`. Віртуалізовані списки зберігають плавність прокручування незалежно від обсягу даних, а файлова маршрутизація робить структуру навігації наочною.
